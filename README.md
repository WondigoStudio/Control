# Status Monitor — сайт для мониторинга сайтов и ботов

Простой self-hosted сервис: проверяет доступность твоих сайтов и Telegram-ботов,
хранит историю в SQLite, показывает дашборд и шлёт уведомления в Telegram при падении.

## Возможности

- Проверка HTTP-сайтов (статус-код, время ответа)
- Проверка Telegram-ботов (через метод `getMe`)
- Проверка любого health-эндпоинта (тоже через HTTP-тип)
- История проверок, аптайм % за 24ч и 7д
- Уведомления в Telegram при падении/восстановлении
- Веб-дашборд с карточками и графиком времени ответа

## Установка

```bash
npm install
cp .env.example .env
```

В `.env` при желании укажи `NOTIFY_BOT_TOKEN` и `NOTIFY_CHAT_ID` — это отдельный
Telegram-бот (создать через @BotFather), который будет слать ТЕБЕ уведомления.
Если не указать — уведомления просто будут писаться в консоль сервера.

## Настройка объектов мониторинга

Отредактируй `monitors.json`. Три типа записей:

```jsonc
{
  "id": "уникальный-id",
  "name": "Человекочитаемое имя",
  "type": "http",              // или "telegram_bot"
  "url": "https://...",        // для type: http
  "botToken": "...",           // для type: telegram_bot
  "intervalSec": 60,           // как часто проверять
  "timeoutMs": 8000,
  "expectedStatus": 200        // ожидаемый HTTP-код (для http)
}
```

Для ботов, у которых нет Telegram API (например, свой сервис на сервере),
сделай в самом боте эндпоинт `/health`, возвращающий 200, и мониторь его как `type: "http"`.

```bash
npm start
```

Дашборд будет доступен на `http://localhost:3000`.

- Либо любой Node-хостинг (Render, Railway, Fly.io) — но учти, что бесплатные
  тарифы могут "усыплять" сервис, что сломает регулярность проверок.

## Паутина: как она отличает настоящие изменения от ложных

Паутина обходит сайт и говорит, какие страницы появились, изменились или исчезли. Чтобы не врать, она следует правилам:

- **Сбой загрузки ничего не меняет.** Таймаут, обрыв, 5xx и 429 сначала повторяются (до 3 попыток с паузой). Если страница так и не загрузилась, сохранённые о ней данные не трогаются. Сбой сам по себе не означает ни «изменилась», ни «исчезла».
- **HTTP-ошибки и заглушки не считаются содержимым.** Ответы 403/429/5xx и страницы вида «Just a moment…», «Access denied» пропускаются, а не сравниваются.
- **«Исчезла» только после повторных 404/410.** Страница, до которой не дошли по ссылкам (пункт меню пропал, сбой родительской страницы, лимит глубины), открывается напрямую. Живая страница обрабатывается как обычно. Удалённой она считается, только если ответила 404 или 410 несколько обходов подряд (`removeAfterMisses`, по умолчанию 2). Если не открылась сама стартовая страница, обход прерывается и ничего не меняется.
- **«Изменилась» только после подтверждения.** Страница загружается второй раз через пару секунд. Блоки, которые различаются между двумя загрузками (случайные карточки, счётчики, «N минут назад»), в сравнение не входят. Резкое сокращение страницы (меньше трети прежнего размера, например обрезанный ответ) принимается, только если повторится в следующем обходе.
- **Сравнивается видимый текст и адреса ссылок**, а не разметка. Случайные id, nonce, cache-busting и CSS-классы изменением не считаются. Метки `utm_*`, `fbclid`, `gclid`, `yclid` и подобные в адресах отбрасываются. Старое поведение (по всей разметке) включается настройкой `crawl.hashMode = "markup"`.
- **Вернувшаяся страница** отмечается событием «Страница снова доступна».
- Два обхода одного монитора одновременно не запускаются (ручной запуск во время обхода по расписанию получит 409).

Настройки (в `crawl` монитора, всё необязательно): `hashMode` (`"text"` по умолчанию или `"markup"`), `removeAfterMisses` (1–10, по умолчанию 2), а также прежние `watchSelector` и `ignoreSelectors`.

После обновления все страницы один раз переучиваются молча, без событий «изменилась»: способ подсчёта отпечатка поменялся. В журнале обхода это видно строкой «переучено без события N». Строки «ждут подтверждения» и «нестабильных» показывают, что краулер отсёк сомнительные случаи.

Автотест на сайте, который нарочно сбоит: `npm i --no-save pg-mem && node test/crawler-scenario.js`. Он использует pg-mem вместо Neon и ничего не пишет в вашу базу.

## Структура проекта

```
server.js       — Express-сервер + планировщик проверок (node-cron)
checker.js      — логика проверки сайтов и ботов
db.js           — работа с SQLite (better-sqlite3)
notifier.js     — отправка уведомлений в Telegram
monitors.json   — список объектов мониторинга (редактируешь ты)
public/         — фронтенд дашборда (HTML/CSS/JS без фреймворков)
data/monitor.db — база данных (создаётся автоматически)
```

## Как добавить email-уведомления вместо/вместе с Telegram

В `notifier.js` добавь свою логику отправки (например, через `nodemailer`)
и вызови её в `checker.js` рядом с текущим вызовом `notify()`.
